# Задача 25: Процент посещаемости

**Студент:** Сидоркевич А.В.

## Постановка задачи

Подсчёт % посещаемости и список студентов ниже порога.

- **Тесты:** деление на ноль (нет занятий).
- **AI-review:** сообщения об ошибках.

## Запуск и тесты

**Язык:** Python 
**Зависимости:** `pytest` (внешних библиотек для самой логики не требуется).

Установка:

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Запуск тестов:

```bash
pytest tests/ -v
```

Демо-сценарий (опционально):

```bash
python -m app.attendance
```

Ожидаемый результат: все тесты зелёные, включая кейс `total_classes = 0`.

### Ключевые промпты

1. **Генерация кода.**
   > «Напиши на Python класс `AttendanceTracker`: в конструкторе `total_classes`, метод `record_attendance(name, attended)`, метод `get_students_below_threshold(threshold_percent)` возвращает студентов с процентом строго ниже порога. Предусмотри валидацию входных данных.»

2. **Генерация тестов.**
   > «Напиши тесты на pytest для `AttendanceTracker`. Обязательный кейс — `total_classes = 0` (деление на ноль). Добавь негативные сценарии: отрицательные значения, посещено больше, чем всего занятий, некорректный порог.»

3. **Уточнение поведения на нуле.**
   > «Если занятий ещё не было (`total_classes = 0`), что должен возвращать метод списка отстающих: исключение, `None` или пустой список? Обоснуй с точки зрения контракта API и бизнес-логики.»

4. **AI-review.**
   > «Проведи ревью кода: читаемость, краевые случаи, качество и информативность сообщений об ошибках. Предложи конкретные улучшения текстов исключений.»

5. **Проверка на лишние зависимости.**
   > «Нужны ли для этой задачи внешние библиотеки (`pandas`, `decimal`, работа с датами)? Обоснуй, если нет.»

Полные формулировки и комментарии к итерациям — в [`docs/prompts.md`](docs/prompts.md).

### Что ИИ сделал хорошо / плохо

**Хорошо:**
- сразу выдал рабочий скелет класса с адекватной структурой хранения (`dict` «имя → посещения»);
- корректно применил `ValueError` для невалидных аргументов;
- быстро набросал базовые тесты и негативные сценарии, экономия времени на бойлерплейте.

**Плохо:**
- сообщения об ошибках вида `raise ValueError("Invalid value")` — при отладке непонятно, что именно не так и с каким студентом;
- в расчёте процента сразу написал `(attended / total_classes) * 100` без защиты от нуля;
- тест на `total_classes = 0` предложил через `pytest.raises(ZeroDivisionError)`, то есть зафиксировал падение как «правильное» поведение;
- не провалидировал диапазон самого порога (`0..100`);
- на пятый промпт сначала предложил `pandas` — избыточно для задачи на целых числах.

### Что исправлено вручную

1. **Контракт ошибок.** Введён собственный класс `AttendanceError(ValueError)` вместо разрозненных `ValueError` — вызывающий код может ловить ошибки домена отдельно.
2. **Тексты исключений.** В каждое сообщение добавлен контекст: имя студента, фактическое значение, допустимый диапазон. Пример: `Студент 'Петр' не мог посетить 15 занятий: всего занятий 10`.
3. **Деление на ноль.** При `total_classes == 0` метод возвращает пустой список, а не бросает исключение и не падает. Обоснование: если занятий не было, порог не нарушен никем — отчёт в начале семестра должен быть пустым, а не аварийным. Тест переписан с `pytest.raises(ZeroDivisionError)` на проверку пустого результата.
4. **Валидация порога.** Добавлена проверка `0 <= threshold_percent <= 100`, которую ИИ пропустил.
5. **Граница порога.** Явно зафиксировано и покрыто тестом строгое сравнение `<`: студент ровно на пороге в список не попадает.
6. **Лишние зависимости убраны.** Оставлен только `pytest`; `pandas`/`decimal` не нужны, так как считаются количества занятий, а не деньги.

### Этические и практические риски

- **Утечка данных.** В промпты не попадали реальные ФИО, номера групп и ведомости — только вымышленные имена. Секреты и токены в репозитории отсутствуют.
- **«Уверенный» неверный код.** Модель без оговорок выдала деление без проверки нуля и тест, закрепляющий падение. Формально код «работает», но ломается на реальном сценарии первого дня семестра — это главный найденный дефект.
- **Галлюцинации API / лишние зависимости.** Предложение `pandas` для тривиальной арифметики — типичный пример раздувания стека; отклонено.
- **Слепое копирование.** Черновик ИИ не переносился в репозиторий как есть: изменены контракт ошибок, поведение на нуле и валидация, тесты прогнаны локально.
- **Лицензии.** Сгенерированный код — типовая учебная логика без заимствования сторонних проектов; совместимость лицензий не нарушена.

## Итог

ИИ полезен как ускоритель черновика и генератор шаблонных тестов, но краевые случаи и контракт API приходится определять вручную: модель выбирает «технически допустимое» поведение (бросить ошибку), а не «бизнес-корректное» (вернуть пустой отчёт).
